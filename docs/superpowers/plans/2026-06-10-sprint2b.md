# Sprint 2b Implementation Plan — Connections API, Onboarding Pipeline, MCP Restructure, Resolution Queue

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the Phase 1 control layer: entity-vocabulary MCP everywhere (no vendor tool names, no `SignalID`), a `connections` table + REST API with one-active-source-per-category, a Temporal-backed idempotent onboarding pipeline with decommission-on-removal, and Resolution Queue write paths.

**Architecture:** Track 3 (MCP restructure) lands FIRST — it rewrites contracts (`TagDescriptor` replaces `SignalDescriptor`; `SignalID` deleted) and renames every connector tool to entity vocabulary, so later tracks wire against stable names. Track 1 adds the `connections` table in the MAR database (Alembic 0003, breaking: `asset_aliases.source_system` → `connection_id` FK) plus `packages/connections_api` (FastAPI). Track 4 adds binding write paths to the MAR repos and exposes them in the same API app. Track 2 adds Temporal to compose and `packages/onboarding` (workflow + activities + worker + FastAPI trigger/query app + `onboarding_runs` table, Alembic 0004).

**Tech Stack:** as Sprint 2a, plus `temporalio` (Python SDK), Temporal `auto-setup:1.22` + `temporalio/ui` in compose, FastAPI apps with OpenAPI at `/docs`.

**Ground rules:** same as the Sprint 2a plan (TDD, conventional commits, skip-if-unreachable for live services, `uv sync` after pyproject changes, `task lint` before commits).

**Reality notes (verified against the repo)**
- Current tool names that must die: `assets.resolve/get/search` (→ `asset.*`), `pi.get_series/get_summary/get_event_frames`, `maximo.get_workorders/get_failure_history/preview_writeback/commit_writeback`, `documents.search/fetch`. Keep: `kg.*`, `asset_hierarchy.*` (internal/onboarding namespace), `uns.*` + `opc_ua.*` (not vendor words; not part of the six entity MCPs), `sap_pm.*` (parked, excluded from `task test`).
- The spec's "old names" (`pi.get_snapshot`, `pi.list_tags`, `maximo.search_wo`…) don't all exist; the **target** tool lists are authoritative.
- `SignalID` is used by: `contracts/_ids.py`, `signal.py` (`SignalDescriptor`), `measurement.py`, `alarm.py`, `connector_sdk/ports.py` + `orchestrator.py` + `series.py` + `context.py`, and the pi/echo/opc_ua/mqtt(sap_pm) connectors and their tests.
- Maximo writeback tools (`preview_writeback`/`commit_writeback`) and `get_failure_history` are NOT in the entity tool list → unregister them (delete the tool classes and tests; git history preserves them; they're Tier-4/Sprint-4 scope).
- The PI simulator lacks tag-discovery/current-value/single-event-frame routes. Real PI Web API has them, so add to the sim: `GET /points?nameFilter=<glob>` (Items of `{WebId, Name, Path, Descriptor, EngineeringUnits}` built from the signal index, Name = `"<TAG>.<role>"`), `GET /points/{webId}`, `GET /streams/{webId}/value` (latest value at window_end or `time` param), `GET /eventframes/{id}` (id = the event frame `Name`). The sim is a separate uv project (`rca_simulator/`) with its own tests.
- Entity tools are **hand-wired** FastMCP tools (MAR-server style: explicit `ToolResponse.ok/fail`, `ProvenanceAccumulator`, `map_source_error`) — NOT `@evidence_tool`. The orchestrator + `SignalResolver` port survive only for echo/opc_ua/mqtt/sap_pm (typed with plain `UUID` after SignalID removal).
- MAR DB is the home of `connections` and `onboarding_runs` (same Alembic chain: 0003, 0004). Migrations 0001/0002 set the precedent that breaking migrations may require a recreated dev DB; 0003 must backfill correctly on a seeded Sprint-2a DB regardless.
- `SOURCE_SYSTEM_CATEGORIES` (models.py) is deleted in Track 1; new category vocabulary: `hierarchy / historian / cmms / document / operator_log`. Legacy backfill mapping: `maximo→cmms (active)`, `sap_pm→cmms (disabled — avoids the one-active-per-category index clash)`, `pi_af→hierarchy (active)`, `uns→historian (active)`.
- Docker may be flaky on this machine; every live-service test must skip cleanly.

**Decisions locked here (risk callout #5 and routing):**
- *Process topology:* factories return per-entity FastMCP servers; tests exercise them in-process via in-memory clients. A `scripts/run_mcp_host.py` (tiny) mounts all six in one process for manual runs — single-process-multi-mount, documented in `docs/mcp/`.
- *Routing:* new `connector_sdk.routing` module. `ConnectionInfo` dataclass `{connection_id, plant_id, category, connector_type, base_url, extra_config}`; `ConnectionRouter` Protocol `async def active(plant_id, category, connection_id=None) -> ConnectionInfo`; `StaticConnectionRouter` (dict-backed, tests) and a Postgres-backed `MarConnectionRouter` (in `rca_mar.connections`). Entity tools parse `plant_id` from the canonical_id (`asset:{plant}:{unit}:{name}` — add `parse_canonical_id` helper to contracts), then `router.active(...)`.
- *Tag identity:* new contract `TagDescriptor{canonical_id: str, tag_name: str, role: str | None, source_unit: str | None, qudt_unit: str | None, pressure_reference, description}` — no UUIDs. `MeasurementSeries.signal: SignalDescriptor` → `MeasurementSeries.tag: TagDescriptor`; `Measurement` drops `signal_id`; `Alarm.signal_id` → `Alarm.tag_name: str | None`; delete `signal.py`/`SignalDescriptor` and `SignalID`. Canonical target units for raw units come from a small `canonical_unit_for(raw_unit)` map added to `connector_sdk.units` (psig→kPa, degF→DEG_C, etc.), consistent with the template roles file.
